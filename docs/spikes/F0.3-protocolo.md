# Spike F0.3 · Protocolo (2026-10-21)

**Resultado: verde.** Las tres confirmaciones de ADR-0003 pasan y el salto de ADR-0002 queda muy
por debajo del tope.

## Montaje

```
Claude Code / MCP Inspector / cliente FastMCP
        │  MCP 2026-07-28 (streamable HTTP)
  puerta terranova (FastMCP 4.1.3, SDK mcp 2.3.0) :8100
        │  MCP 2025-11-25, Bearer de servicio
  arcgis-mcp de GEO Copilot (mcp 1.28.1, geo_mcp_kit) :9400
        │  REST
  IGAC · Base_Catastral_Publica_del_Gestor_IGAC_06_2026 (capas 14 R_TERRENO y 7 U_TERRENO)
```

- La puerta (`src/terranova/puerta.py`) expone `igac_predio_en_punto(lon, lat)` y devuelve un
  subconjunto de `rt/1` (`src/terranova/sobre.py`). La fuente está escrita a mano: el catálogo
  llega en F1.
- La puerta abre una sesión MCP con el conector al arrancar y la reutiliza en cada llamada.
- El conector corrió como proceso local (no en Docker) para no gastar memoria. En la red de Docker
  el salto será algo mayor que en loopback, pero queda margen de sobra.

## Latencias (`scripts/medir_salto.py`)

| Medida | n | p50 | p95 | máx |
|---|---|---|---|---|
| Salto `ping` puerta → conector | 200 | 2,2 ms | **3,1 ms** | 3,4 ms |
| Salto `tools/list` | 50 | 2,7 ms | 3,7 ms | 3,8 ms |
| De punta a punta, con la fuente | 5 | 1,5 s | 6,5 s | 7,7 s |

El salto se mide con `ping` y `tools/list`, que no llegan a la fuente. A la fuente solo van cinco
llamadas, de dos consultas cada una. ADR-0002 estimaba 10–30 ms y lo medido en loopback es 3 ms.

Lo que pesa es la fuente: ArcGIS Online respondió entre 1,5 s y 7,7 s. Eso es tarea de F2 (caché y
cortacircuitos), no del protocolo.

## Hallazgos

- **Dato sucio en la fuente:** el campo `codigo_municipio` de R_TERRENO trae `23175` para un predio
  de Chía (25175). La puerta toma el municipio de los cinco primeros dígitos del código predial.
  Hay que añadir un canario para esto en F1.
- **Corte vigente:** al 2026-10-21 el corte más reciente publicado sigue siendo `06_2026`; no hay ni
  07 ni 08. Existe además `Base_Catastral_Publica_IGAC_de_octubre`, que hay que revisar en F1.5 al
  descubrir el corte.
- **SDK `mcp` 2.x:** los campos pasan a snake_case (`ToolAnnotations(read_only_hint=…)`,
  `protocol_version`). Hay que tenerlo en cuenta al migrar los conectores después de M1.
- **Windows:** la consola es cp1252, así que los scripts que imprimen símbolos reconfiguran stdout a
  UTF-8.

## Cómo repetirlo

1. Conector, en un entorno aparte con `mcp==1.28.1`, `uvicorn`, `httpx`, `pyproj` y
   `-e ../GEO_COPILOT/packages/geo_mcp_kit`. Desde `../GEO_COPILOT/services/arcgis_mcp`:
   `ARCGIS_MCP_KEYS='[{"name":"terranova-puerta","key":"<LLAVE>","scopes":["arcgis:read"],"rate_limit_per_min":600}]' ARCGIS_ALLOWED_DOMAINS=services2.arcgis.com python -m arcgis_mcp.server`
   (o el perfil de `docker-compose.yml`).
2. Puerta: `TERRANOVA_ARCGIS_MCP_KEY=<LLAVE> uv run terranova`, que queda en `http://127.0.0.1:8100/mcp`.
3. Medida: `TERRANOVA_ARCGIS_MCP_KEY=<LLAVE> uv run scripts/medir_salto.py`.
4. Claude Code: `{"mcpServers":{"terranova":{"type":"http","url":"http://127.0.0.1:8100/mcp"}}}`
   con `claude --mcp-config …`. Inspector:
   `npx @modelcontextprotocol/inspector --cli http://127.0.0.1:8100/mcp --transport http --method tools/list`.
